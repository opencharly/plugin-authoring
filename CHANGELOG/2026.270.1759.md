# 2026.270.1759 — fix(authoring)!: ship a self-contained CUE schema (no schema-less plugin)

## Summary

Eradicate the schema-less plugin exception for `plugin-authoring`: every plugin MUST serve a non-empty, self-contained CUE schema over `Describe` (**opencharly/sdk#314**; there is no schema-less plugin). This plugin passed `nil` as the schemaFS and served an EMPTY `schema_cue`, which makes `charly` panic at process start (`loadBuiltinPluginUnits`) once charly pins the post-sdk#314 contract — the direct blocker of the **charly host leg** (opencharly/charly#714).

Ordered per-repo unit of the R5 cutover tracked in **opencharly/charly#712**.

- `plugin.go` — `//go:embed schema/*.cue` + `sdk.NewMeta(calver, caps, schemaFS)` instead of `nil`; the stale "ships no schema" comment corrected.
- `schema/authoring.cue` — NEW: a package-less, self-contained doc schema (`#AuthoringPlugin`) naming the plugin's command surface.
- `schema_serve_test.go` — NEW: `TestNewMetaServesNonEmptySchema`, `TestServedSchemaSplicesOntoHostBase` (the real `base ++ plugin` splice), and `TestSchemaCommandsMatchGoSource` (pins `#AuthoringPlugin.commands` to `authoringCommandWords` so the doc schema cannot drift from the declared surface — R3).
