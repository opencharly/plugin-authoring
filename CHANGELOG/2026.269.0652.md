# 2026.269.0652 — feat: declare the box command parent on the wire (hard cutover)

## Summary

Make the parent part of every command word this plugin serves its full capability IDENTITY:
the manifest lists `command:<word>:box` and `NewMeta` sets
`ProvidedCapability.CommandParent = authoringCommandParent`, so charly keys the provider at
`command:<word>:box` in EITHER placement. The Go `CommandParent()` method — the old carrier
of the parent — is **DELETED** in this same change.

This makes every authoring word's identity explicit on the wire — `command:<word>:box` — so
the registry keys it deterministically under the `box` parent instead of relying on a
compiled-in Go interface.

### Classification: this is a HARD CUTOVER, not an additive change

The old spelling `command:<word>` is no longer accepted; the new spelling
`command:<word>:box` replaces it, and the `CommandParent()` method is removed. That is a
modification + removal of existing surface, so the cutover-policy "purely additive" exemption
does NOT apply. It is a one-phase hard cutover: the transitional method is DELETED here, not
deferred, and there is no dual-acceptance path left.

### Why deleting the method is safe against the merged consumer

The safety rests on ONE fact, pasted here rather than asserted: **charly `origin/main` pins
this repo's OLD tag**, so the merged charly never pairs with this PR's new tag.

```
$ git -C charly show origin/main:charly/go.mod | grep plugin-authoring/candy
	github.com/opencharly/plugin-authoring/candy/plugin-authoring v0.2026237.1414
```

The consumer that pairs with the new tag is the charly branch `feat/command-parent-identity`,
which reads the DECLARED wire field and no longer sniffs the method:

```
$ grep -n GetCommandParent <charly feat/command-parent-identity>/charly/plugin_provider_common.go
158:            if p := c.GetCommandParent(); p != "" {
164:    } else if c.GetCommandParent() != "" {
```

The cutover is atomic across the two repos: charly `origin/main` keeps pinning the old plugin
tag (unaffected); this repo's new tag activates only when the charly leg bumps its pin, and
that leg reads the wire field.
